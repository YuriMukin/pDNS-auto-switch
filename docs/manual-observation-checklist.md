# Проверка диагностического сервиса

Сервис **не меняет DNS**. OFF/HOSTNAME/BLOCKED в журнале — рекомендации, не выполненные действия.
Периодического опроса нет: используются системные сетевые callbacks.

## Как пользоваться

1. Для чтения имён Wi-Fi предварительно выполните проверку подключённой сети и предоставьте
   точную геопозицию при использовании приложения. Без точного разрешения или включённой Location новый location-сервис не запускается; UI объясняет необходимые действия.
2. При необходимости добавьте текущий Wi-Fi в доверенные.
3. В карточке «Наблюдение за сетью» нажмите «Запустить».
4. Оставьте «Записывать журнал» включённым. Кнопка сохранения создаёт `pDNS auto switcher.log` в «Загрузках». Внутри приложения хранится до 50 000 записей; при переполнении удаляется старейшая десятая часть. Сохранение не очищает историю.
5. Завершите сеанс кнопкой «Остановить». Перезапуск приложения сам наблюдение не включает.

Формат: `timestamp - net condition - recommendation`. Время содержит часовой пояс устройства.
`ui=BACKGROUND;screen=OFF` означает, что callback обрабатывался при невидимой Activity и
выключенном экране. `event` и монотонное `elapsed_ms` позволяют отличить новые события от кэша.
`ssid=READABLE;trust=YES` означает прочитанный доверенный SSID; само имя не сохраняется.

## Матрица

| Сценарий | Ожидаемый результат |
|---|---|
| Запуск в доверенном Wi-Fi | RUNNING, в журнале свежая рекомендация OFF. |
| Недоверенный Wi-Fi, mobile или нет сети | HOSTNAME; если провайдера нет — BLOCKED. |
| Недоступен SSID / Location off / отказ разрешения | Нет ложного доверия; причина явно указана, DNS не меняется. |
| Переходы при скрытой Activity и выключенном экране | Новые строки с правильными ui/screen; старое имя не подменяет новое чтение. |
| Изменение списка при наблюдении | Рекомендация пересчитывается по событию DataStore. |
| Повторные одинаковые capabilities | Нет бесконечного потока одинаковых записей. |
| Поздний callback потерянной сети | Не возвращает рекомендацию OFF из старого SSID. |
| Явная остановка | После SERVICE_STOPPED новые сетевые события не добавляются. |
| Перезапуск процесса | История остаётся, сервис STOPPED до нового явного запуска. |
| Очистка | Требует подтверждения, удаляет только приватный журнал, не экспортированные файлы; список и сервис не меняются. |
| Весь сеанс | Фактические DNS mode/provider в начале и конце совпадают. |

Специального сценария VPN не требуется: сервис ориентируется на физический Wi-Fi и не
блокирует рекомендации из-за наличия VPN. Несколько неоднозначных физических Wi-Fi — отдельный случай.

## Уже проверено

На эмуляторе Android 17: запуск через UI, доверенный SSID → OFF, формат трёх полей без имён
сетей, новые события отключения/подключения в фоне с выключенным экраном, остановка подписок,
сохранение после перезапуска процесса, отсутствие автоматического старта и очистка.
Во всех этих проверках фактические DNS mode/provider сохранялись. Светлая и тёмная темы просмотрены.

После нового подключения в фоне эмулятор скрывал SSID: получена рекомендация HOSTNAME с
причиной SSID_UNAVAILABLE. Это результат эксперимента, а не доказательство чтения SSID на Pixel.
Проверка на основном телефоне, длительный сеанс 30+ минут, системная остановка Active apps,
низкая память, отказ IO и действие уведомления пока отдельно не подтверждены.

## Повторная проверка location-сервиса и длительного сеанса

- Обновить APK поверх установленного; запустить сервис из видимого приложения с точной геопозицией и включённой Location.
- Убедиться, что запись включена. Наблюдать при закрытой Activity и выключенном экране; переключить доверенный Wi-Fi → недоверенный → доверенный.
- После возвращения сохранить файл в «Загрузки». Анализировать именно новые события `ui=BACKGROUND` и `ssid=READABLE`, а не только сведения после открытия Activity.
- `stage=RAW` может содержать краткие промежуточные рекомендации. `stage=STABLE` появляется после 750 мс без изменений, не после каждого переходного callback.
- Отключить запись: новые сетевые события не попадают в файл. Перезапуск приложения сохраняет выбор; включить обратно для суточного теста.
- Остановить сервис: SERVICE_STOPPED попадает на диск; повторное открытие сохраняет историю, но не запускает наблюдение автоматически.
- Повторный экспорт не уничтожает предыдущий. Файл читается как UTF-8, содержит три столбца и не содержит имён сетей.
- Проверить отказ разрешения/Location off до старта: понятное сообщение, без падения. Отзыв разрешения во время работы может завершить процесс средствами Android.

onDestroy не гарантирован при системном убийстве. Уже записанная история остаётся; возможна потеря очереди последних событий. 50 000 записей — ограничение по количеству, а не гарантия хранения ровно суток при любой частоте изменений.

## Проверено после исправления

На эмуляторе Android 17: запрос разрешения перед запуском, свежий читаемый SSID и STABLE OFF
после переподключения при невидимой Activity и выключенном экране, корректный .log в Downloads,
остановка записи переключателем, финальный SERVICE_STOPPED на диске, история после force-stop
и отсутствие автозапуска. DNS mode/provider не изменились; ошибок AndroidRuntime не найдено.
Суточная работа и повторный тест на Pixel остаются непроверенными.
